# Technical contracts

Every number and format in the design is defined here once. Code, tools and other design files
refer to these names. Changing a contract is a reviewed `docs/design/` PR first, code second.

## Simulation

| Item | Contract |
|---|---|
| Tic rate | **35 Hz**. One gameplay update per tic. Rendering is decoupled and never changes state. |
| Fixed point | `fix_t` = `int32_t`, **16.16**. `FIX_ONE = 65536`. Multiply via `int64_t` intermediate, `fix_mul(a,b) = (fix_t)(((int64_t)a*b) >> 16)` (arithmetic shift), `fix_div` via `int64_t` with truncation toward zero. |
| Speeds | Stored per tic in 16.16. Conversion from the design tables: `per_tic = round(units_per_sec * 65536 / 35)`. The tables give both. |
| Angles | `angle_t` = `uint16_t`, 65536 = full turn, 0 = east (+x), counter-clockwise, y grows north. Trig: `fine_sin/fine_cos` tables of 4096 `fix_t` entries indexed by `angle >> 4`, generated at build time by a C generator (floating point allowed there, output is a checked-in-free generated header). |
| Durations | Always in tics. 1 s = 35 tics. |
| RNG | One gameplay RNG: xorshift32, state `uint32_t`, seeded at level start from `level_seed = 0x9E3779B9 ^ (level * 2654435761u)` and the demo's `seed` line. Rendering, audio and menus use a separate RNG that never touches game state. |
| Damage | `damage = base + rng() % (spread + 1)`, both integers from the stats tables (`base..base+spread`). |
| Gameplay floats | Forbidden. Floats are allowed only in the renderer projection maths, offline tools and the trig-table generator. |
| State hash | 64-bit FNV-1a over the canonical serialisation of game state: tic, RNG state, player (pos, angle, momentum, health, armour, ammo, weapons, keys, powerup timers), every thinker in creation order (type, pos, angle, state, tics left, health, target id), every door/switch/pushwall state, level counters. Pointers are never hashed; ids are. |
| Skill | 1 "Kitten" (easy), 2 "Tomcat" (normal, the reference), 3 "Sabretooth" (hard). Entity placement has per-skill flags. Kitten: player takes half damage (rounded down, min 1) and ammo pickups give 1.5x. Sabretooth: enemy wind-ups are 25% shorter (rounded down) and pain chance halved. |

## World

| Item | Contract |
|---|---|
| Tile | 1 world unit square, 64x64 px textures. Wall height 1 unit everywhere. |
| Map size | Up to 64x64 tiles. |
| Camera | Eye height 0.5 units (centred on the wall), horizontal FOV 90 degrees, projection plane distance 160 px, view 320x208 above a 32 px status bar. Square pixels. |
| Player | Radius 0.25 units (16384). Walk 4 u/s (7490/tic), run 7 u/s (13107/tic), turn 180 deg/s keyboard (1872 angle units/tic). Movement is accelerated, max speed reached in 4 tics, friction stops in 4 tics. Collision: circle vs solid tiles, axis-separated slide. Use reach 0.75 units. |
| Sprites | Billboards anchored at bottom-centre on the floor (or at a stated height in units for projectiles). Scale 64 px per unit like walls. Sprites taller than 1 unit appear only under sky cells. |
| Lighting | `row = clamp(32 * dist / VIEW_DIST + cell_dark, 0, 31)` where `VIEW_DIST = 16` units and `cell_dark` is the map cell's darkness 0..31. Walls: once per column (`cell_dark` of the wall's cell). Floors/ceilings: the distance part once per row; `cell_dark` is added per pixel from the cell being sampled (one add and a clamp, no search). Sprites: once per sprite (`cell_dark` of the sprite's cell). Fullbright palette entries (`art-bible.md`) ignore it. |

## Files and formats

All binary formats are little-endian. One implementation each, in `src/bast/` (`libbast.so`),
used by the engine (linked statically from the same sources) and by Python tools through the
ctypes wrapper `tools/bast.py`. Nobody writes a second reader or writer.

### Palette

- Source: `assets/src/palette/catlantis.gpl` (GIMP palette, 256 entries, each line named, e.g.
  `sand_07`). Entries named `reserved_*` exist so indices never move; they are excluded from
  nearest-colour matching until an asset PR names them. Fullbright entries are named `fb_*`.
- Built: `assets/gen/palette.bin`, 768 bytes RGB, plus `assets/gen/palette_flags.bin` (256 bytes:
  bit0 reserved, bit1 fullbright, bit2 transparent).
- Index **255 is transparency** (#FF00FF), **0 black**, **1 white**.

### Colormap

`assets/gen/colormap.bin`: 32 rows x 256 bytes. Row 0 is identity. Generated by
`tools/colormap.py` (see `art-bible.md` for the shading and warm-shift formula). Oklab nearest
search is done by `bast_palette_nearest()` in libbast, never reimplemented.

### TEX (textures, sprites, HUD art, fonts)

```
offset size  field
0      4     magic "TEX1"
4      2     width  (uint16, 1..1024)
6      2     height (uint16, 1..1024)
8      2     origin_x (int16)  sprite anchor, px from left (bottom-centre for world sprites)
10     2     origin_y (int16)  px from top
12     1     flags: bit0 has_transparency, bit1 fullbright (skip colormap)
13     3     reserved, zero
16     w*h   palette indices, COLUMN-MAJOR (x outer, y inner)
```
Column-major because walls and sprites are drawn as columns. libbast API:
`bast_tex_load/save/free`, `bast_tex_from_rgba(palette, rgba, w, h)` (Oklab nearest, no
dithering, alpha < 128 becomes index 255).

### Sprite naming

`<sprite>_<anim>_d<dir>_f<frame>.tex`, e.g. `mutt_walk_d3_f1.tex`. `dir` 0..7: d0 = the thing faces
the camera, then the camera moves counter-clockwise around it in 45 degree steps (d4 = back). Pickups
and effects without facing use `d0` only. Frame index from 0.

### Map (`.vmap`, binary, in `maps/`)

```
header: magic "VMAP", uint16 version=1, uint8 width, uint8 height, char name[32],
        uint8 sky_tex, uint8 music, uint16 par_seconds, uint16 entity_count,
        uint16 texture_count, then texture_count x char[16] texture names (index 0 = none)
cells:  width*height records, row-major from (0,0) south-west:
        uint8 wall, uint8 floor, uint8 ceil (0 = sky), uint8 dark (0..31),
        uint8 dark_alt (0..31, used after a LIGHTS entity's tag fires), uint16 flags, uint8 tag, uint8 param
entities: entity_count records: uint16 type, int32 x, int32 y (16.16), uint16 angle,
        uint16 flags (bit0..2 skill 1..3, bit3 ambush/deaf, bit4 secret-only), uint8 tag, uint8 param
```
Cell flags: `SOLID`, `DOOR`, `PUSHWALL` (secret, slides 2 tiles away from the user), `SWITCH`,
`EXIT` (switch that ends the level), `SECRET` (counts when entered), `DAMAGE` (param = damage per
16 tics), `ONEWAY` (door openable only from the side its param points to), `START_OPEN`,
`BLOCK_MONSTER`, `BLOCK_ALL` (impassable but drawn as floor, e.g. water), `TRIGGER` (walk-over fires tag). Door `param`: bits 0-1 key (none/green/blue/violet),
bits 2-3 mode (0 auto-close after 140 tics, 1 stays open, 2 switch-only, 3 timed: closes param2
seconds after its switch, stored in the switch cell's param), bits 4-5 `ONEWAY` side (0 north,
1 east, 2 south, 3 west: the player must stand past that edge of the door cell to open it). Doors
take 32 tics to open or close, block until fully open, never start closing while the player overlaps
the cell, and re-open if the player enters a closing one. Use (`BT_USE`, rising edge) targets the first
non-empty tile within 0.75 units along the view (grid DDA). `START_OPEN` doors ignore use and
auto-close; a tag closes them once, after which they follow their mode. A tag fires every door and pushwall with
the same tag: closed ones open, `START_OPEN` ones close. This is how layouts change.

Special entity types fire or react to tags: `KILL_TRIGGER` (fires its `param` tag when every
enemy carrying its `tag` is dead), `PICKUP_TRIGGER` flag on a pickup (fires its tag when taken),
`LIGHTS` (when its tag fires, every cell switches from `dark` to `dark_alt`), `WAYPOINT` (named,
demo navigation only), `PLAYER_START`, `BOSS_POD`, `RESPAWN_ITEM` (L8 only). Entity names are an
optional trailing table: uint16 count, then (uint16 entity index, char[16] name).

Maps are authored in the editor (M2). Before the editor exists, maps are produced by
`tools/mkmap.py` from an ASCII layout in `maps/src/*.txt`; the `.vmap` is the committed source of
truth once the editor exists.

### Demos (`.demo`, text, in `demos/`)

Human-writable, line-based, `#` comments. Header lines first:
```
vsdemo 1
level 1          # level number, same as --warp
skill 2
seed 0
map m1test       # optional: play maps/<name>.vmap instead of maps/level<N>.vmap
```
The optional `map` line is for test maps that are not numbered levels (`m1-walk` uses `m1test`).
Map choice in `build/game`: `--map` file, else `--warp N`, else the demo's `map`, else its `level`.
Body, executed in order, each line consuming tics:

| Line | Meaning |
|---|---|
| `in <n> <fwd> <side> <turn> <buttons>` | Raw input for n tics. fwd/side -127..127 (fraction of run speed), turn in angle units per tic, buttons a string of `F` fire, `U` use, `R` run, `1`-`7` weapon, `-` none. Recorded demos contain only `in` lines. |
| `wait <n>` | n tics of no input. |
| `goto <tx> <ty> [max]` | Path (BFS over tiles, 4-connected, through doors the player can open) to the tile centre, opening doors on the way. Fails after `max` tics (default 1050). |
| `goto @<name> [max]` | Same, to a waypoint entity (`type WAYPOINT`, name in the map's entity names). |
| `face <angle_deg>` / `face <tx> <ty>` | Turn in place, fastest direction. |
| `use` | Press use for one tic facing the current direction. |
| `weapon <n>` | Select weapon slot n. |
| `fire <n>` | Hold fire for n tics. |
| `face nearest` / `fire nearest [max]` | Turn to (and shoot) the nearest visible live enemy until it dies or `max` tics. (M3) |
| `clear [radius] [max]` | Fight visible enemies within radius (default 10 units) until none is visible and awake. (M3) |
| `expect <stat><op><value>` | Assert on the stats (e.g. `expect exit=1`, `expect health>=20`). Failure makes the run exit 2. |

High-level commands are resolved each tic from game state into the same per-tic input a player
produces, so they are deterministic and survive balance changes better than raw input.

### Archives (M2)

`assets/gen/game.pak`: magic "VPAK", uint32 count, then directory of (char name[56], uint32 offset,
uint32 size), 64 bytes per entry, then data. Names are paths relative to `assets/gen/` with `/`
(`sfx/door_open.snd`), 1..55 chars, NUL-padded, unique; offsets count from the start of the file.
The field was 32 bytes until #25 widened it: generated names such as
`fx/teleport_sparkle_loop_d0_f0.tex` (34 chars) did not fit. Built by `tools/pak.py` via libbast. Until it exists the engine loads loose
files from `assets/gen/`.

### Audio files

Sound effects `assets/gen/sfx/<name>.snd`: magic "SND1", uint32 rate (22050), uint32 sample count,
signed 8-bit mono PCM. Music `assets/src/music/<name>.vmus` text pattern files (see `audio.md`).
